# Ассоциативные разрывы коридора по продольному профилю

Каркас для Civil 3D (.NET) — связь «продольный профиль ↔ области коридора» через
перемещаемые маркеры-разрывы в виде профиля и в плане.

> Каркас выверен под **Civil 3D 2024.2**: сигнатуры геометрии подтверждены, правки
> обёрнуты в блокировку документа. Оставшиеся пометки `// АДАПТ` — это не ошибки, а
> точки конфигурации (стиль профиля, слой, масштабы прокси) и одно место для сверки —
> фильтр применимости набора характеристик (см. ниже).

## Состояние на 8 августа 2026

Весь код модуля — в этой папке. Устаревшая копия `CorridorLinker/` (те же классы
в том же namespace, в сборку не входила) удалена пользователем 8 августа 2026;
этот README лежал в ней и восстановлен из коммита `e5294c2`.

Сделано в этот день (собирается, **в чертеже не проверено ничего**):

- участки разводятся зазором и перестали быть непрерывными; границы двигаются прямо,
  настройки участков больше не стираются — см. «Зазор» ниже;
- ступень профиля стала симметричной: PVI на `S ± 0.0005`;
- отметка низа берётся на `S − 0.0005`: в самой точке `S` профиль вертикален, и что
  вернёт `ElevationAt` — низ или верх — не определено;
- связь пережила перезапуск (`LinkStore`), появилась `RW_BREAKDIAG`;
- исправлено: при полном клампе прокси оставался стоять мимо модели.

Проверять с `RW_BREAKDIAG`: зазор `0.001` между областями, совпадение GUID областей
у маркеров с фактическими, восстановление связи после перезапуска Civil 3D.

Правки хранения (8 августа 2026, тоже **в чертеже не проверены**):

- **владение прокси проверяется по хэндлу, а не по Guid из XData.** У копии
  прокси-линии Guid тот же самый, поэтому раньше удаление копии удаляло
  настоящий разрыв с перестроением коридора, а перетаскивание копии плановой
  линии считало пикет через координаты вида профиля. Теперь маркер ищется через
  `MarkerStore.GetByProxy` (индекс по хэндлу, до этого не читался ниоткуда) плюс
  `StationMarker.OwnsProxy`; копия — просто отрезок. Их список печатает
  `RW_BREAKDIAG` строкой «ничей прокси»;
- запись маркера получила тег `RWBREAK`, версию формата и вид записи
  (маркер/связь): прежний формат начинался сразу с Guid, чужая или битая запись
  была неотличима от своей и пропадала молча. Записи прежнего формата читаются;
- ключ записи в словаре — Guid маркера, запись правится на месте. Ключи
  `MK0..MKn` были позиционными, и каждое сохранение (то есть каждое отпускание
  грипсы) стирало и пересоздавало всю таблицу;
- геометрия и хэндлы переехали в общий `Shared/` (см. ниже).

## Общий код с модулем облицовки

`Shared/RwGeometry` и `Shared/RwHandles` — то, что оба модуля делали каждый
по-своему. Своих реализаций здесь больше нет, и заводить их заново не нужно.

Два исправления приехали вместе с переездом:

- **перпендикуляр к оси в плане** теперь строится через
  `PointLocation(station, offset)` — смещение у него отмеряется по нормали.
  Прежний способ (точка на полметра вперёд, поворот касательной на 90°) грубее
  на кривых малого радиуса, а в конце оси давал нулевой вектор и подставлял
  ось X, то есть прокси-ортогональ смотрела куда попало;
- **`ProfilePointToStation`** вызывал `FindStationAndElevationAtXY` без
  try/catch и без проверки NaN. От падения спасала только проверка в `Drain`.

`RwHandles` ввёл единое правило «стёртое равно пустому»: `Resolve` на стёртый
объект возвращает `ObjectId.Null`, и проверять `IsErased` отдельно не нужно.

Не сделано и мешает работе:

1. **Свойства маркера нельзя изменить после создания** — ни команды, ни рабочей палитры.
   `IsStep`/`StepHeight` захардкожены, а по замыслу это расширяемый набор свойств,
   влияющих на коридор и профиль. Самое важное из оставшегося.
2. Режим редактирования живёт только в сеансе: после перезапуска ручек нет, пока
   не выполнен `RW_EDITMODE`.
3. Набор характеристик на прокси пишется однократно при создании и после перетаскивания
   врёт; `ReadEditFlag` не вызывается ниоткуда — переключатель в палитре ни на что
   не влияет. `GetStepStations` тоже мёртвый код.
4. Связь в чертеже одна, переключения между несколькими нет.
5. `ProfilePVI.Station` объявлен устаревшим в пользу `RawStation`. Разница вылезет
   на осях с уравнениями пикетажа; в модуле и в `CorridorSurfaceCreator.cs` везде
   используется старое свойство.

## Архитектура (модель → единая точка входа → реакторы-детекторы)

```
 Грипса (профиль/план) ┐
 Поле в палитре        ├──►  AssociativeBreakManager  ──►  модель + профиль + области + Rebuild
 Команды RW_*          ┘            ▲   (под BreakSession.Suspend — реактор молчит)
                                    │
        BreakReactor (ObjectModified/Erased/CommandEnded/Idle)
        — НИЧЕГО не меняет сам, только помечает «грязные» маркеры и зовёт менеджер
```

Ключевая идея: все правки сходятся в **один** метод-оркестратор под флагом подавления.
Это и есть защита от циклов перестроения (профиль → коридор → таргеты → профиль).
Источник истины — `StationMarker`, а не геометрия.

## Поток управления при перемещении грипсы

1. Пользователь тянет грипсу прокси (в профиле или в плане).
2. `BreakGripOverrule.MoveGripPointsAt` — дёшево: вычисляет желаемый пикет, **клампит**
   между соседями (буфер 0.1 м), двигает ОБА прокси на новый пикет. Тяжёлого пересчёта нет.
3. Перемещение прокси поднимает `ObjectModified` → `BreakReactor` помечает маркер грязным
   (с хэндлом именно того прокси, что двигали).
4. По `CommandEnded` (или `Idle`) реактор берёт фактический пикет из геометрии прокси и зовёт
   `AssociativeBreakManager.ApplyStationChange`.
5. Менеджер под `Suspend()`: двигает ступень PVI (если IsStep) → переставляет границы
   соседних областей → обновляет прокси → один `Corridor.Rebuild()`.

## Зазор: участки самостоятельны

Разрыв на пикете S раздвигает соседние области на полузазор в каждую сторону: левая
кончается на `S − 0.0005`, правая начинается на `S + 0.0005`. Участки перестают быть
непрерывными и строятся каждый сам по себе. Ступень профиля ставится ровно в этот зазор
(PVI на `S − 0.0005` и `S + 0.0005`), поэтому вертикаль профиля и стык областей — одно
и то же место.

Границы двигаются **прямо**: у `BaselineRegion` есть сеттеры `StartStation` /
`EndStation` / `AssemblyId`, а `RegionGUID` стабилен и годится в ключ. Маркер хранит
GUID пары своих областей. Слияния всех областей с последующим разрезанием больше нет —
оно стирало конструкции, цели и частоты у всех участков разом. Порядок присваивания
обязателен: сначала ужимается отдающая область, потом расширяется принимающая, иначе
на промежуточном шаге они перекрываются.

При удалении разрыва правая область поглощается левой (выживают настройки левого
участка), а соседний справа маркер переводится на выжившую область.

## Команды

- `RW_LINKPROFILECORRIDOR` — мастер: выбрать вид профиля, отметку, коридор; создать плоский
  профиль; навесить на профиль свойство «Режим редактирования».
- `RW_EDITMODE` — переключить режим (если не читаете флаг из палитры реактором).
- `RW_CREATEBREAK` — создать разрыв (пикет из точки в виде профиля; ступень да/нет; высота со знаком).
- `RW_DELETEBREAK` — удалить разрыв (выбрать прокси).
- `RW_SAVEBREAKS` — сохранить модель в чертёж.
- `RW_BREAKDIAG` — диагностика: связь, режим редактирования, маркеры с их привязкой
  к областям и фактические границы областей коридора.

Связь хранится в чертеже (подсловарь `RW_AssocBreaks\Link`) и восстанавливается при
открытии, поэтому переживает перезапуск Civil 3D. Если записи нет, но разрывы в чертеже
есть, связь берётся из любого маркера — он несёт те же четыре хэндла. Восстановление
ничего не пишет в чертёж, чтобы открытие не помечало его изменённым. Связь одна: если
мастер запускали несколько раз, восстановится последняя.

## Сборка под Civil 3D 2024.2

- **Целевой фреймворк:** .NET Framework **4.8**, платформа **x64** (Civil 3D 2024 ещё на .NET Framework;
  на .NET 8 перешёл только 2025).
- **Ссылки (Copy Local = False)** из папки установки `C:\Program Files\Autodesk\AutoCAD 2024\`:
  - `AcCoreMgd.dll`, `AcDbMgd.dll`, `AcMgd.dll` — ядро AutoCAD;
  - `AeccDbMgd.dll` — Civil 3D (Alignment, Profile, ProfileView, Corridor, Baseline);
  - `AecBaseMgd.dll`, `AecPropDataMgd.dll` — наборы характеристик (Property Sets).
- Загрузка в Civil командой `NETLOAD`; точка входа `BreakCommands` уже помечена
  `[assembly: ExtensionApplication]` и `[assembly: CommandClass]`.

## Что подтверждено под 2024 (правок не требует)

- `ProfileView.FindStationAndElevationAtXY(x, y, ref station, ref elevation)` и
  `FindXYAtStationAndElevation(station, elevation, ref x, ref y)`.
- `Alignment.PointLocation(station, offset, ref easting(X), ref northing(Y))`.
- `Alignment.StationOffset(easting(X), northing(Y), ref station, ref offset)` — обёрнут в try/catch:
  при уводе прокси за пределы оси возвращается NaN и пикет не меняется.
- `Profile.CreateByLayout(name, alignmentId, layerId, styleId, labelSetId)`,
  `ProfilePVICollection.AddPVI/RemovePVI`, `BaselineRegion.Split/Merge`, `Corridor.Rebuild()`.
- Правки из реактора обёрнуты в `Document.LockDocument()` — обязательно для пути через `Idle`.

## Единственное место для сверки в вашем проекте

**Применимость набора характеристик.** `PropertyDataServices.AddPropertySet` сработает, только если
набор допускает класс объекта. В каркасе стоит `SetAppliesToFilter(empty, true)` (ко всем).
Если в вашей конфигурации это даёт «not applicable» — задайте фильтр явными именами классов
(профиль — `AECC_PROFILE`, прокси — `AcDbLine`), как уже отлажено в вашем `PropertySetHelper`.

## Известные ограничения каркаса

- Связь в чертеже одна; для нескольких профилей нужен выбор (см. п.3 выше).
- Режим редактирования живёт только в сеансе: после перезапуска он выключен,
  включается командой `RW_EDITMODE`. Без него у прокси нет ручек.
- Второй вид обновляется на завершении драга, не «вживую».
